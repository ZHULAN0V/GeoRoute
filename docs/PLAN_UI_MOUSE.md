# План работ: управление мышью на карте

**Источник:** [TZ_UI_MOUSE.md](TZ_UI_MOUSE.md)
**Проект:** GeoRoute («Майские прогулки»)
**Дата составления:** 2026-05-25

---

## Сводка

Документ разбивает чеклист приёмки из ТЗ на приоритезированные задачи и группирует их в этапы реализации. Каждая задача снабжена ссылкой на пункт чеклиста и затрагиваемые файлы.

### Принципы приоритезации

- **P0 — Критично (фундамент):** без этого остальное не имеет смысла. Состояния карты, выбор маршрута, режим карандаша, разводка ЛКМ/ПКМ/средней кнопки. Это базовая модель взаимодействия.
- **P1 — Высокий:** ключевые фичи редактирования: вершины, КП, модалка номера КП, временная линия предпросмотра.
- **P2 — Средний:** «плюсы», сегменты, их создание и подтверждение — самая объёмная часть, но опирается на P0/P1.
- **P3 — Низкий:** видимость, «Притянуть к тропе», Esc, чистка нижней панели — финальная полировка и UX.

### 1.1. Модель состояний в Redux

- [ ] Ввести явные состояния: «маршрут не выбран», «выбран, карандаш off», «выбран, карандаш on», «выбран сегмент», «выбрана текущая линия» (ТЗ 9.1).
- [ ] Убрать сценарий, при котором клики по карте сами включают режим редактирования (ТЗ 9.1, последний абзац).

### 1.2. Выбор маршрута слева

- [ ] При снятии выбора очищать: выбранный сегмент, текущую линию, временную линию, состояние редактирования.
- [ ] При выборе другого маршрута сбрасывать редактирование, выбранный сегмент, текущую линию.

### 1.4. Верхний индикатор состояния

- [ ] Нет выбора → ничего/нейтральный текст.
- [ ] Выбран, карандаш off → `Выбран маршрут "Название"`.
- [ ] Выбран, карандаш on → `Выбран маршрут "Название" в режиме редактирования. ПКМ — удаление вершин и КП`.
- [ ] Индикатор обновляется сразу при изменении состояния.

### 1.5. Правая панель — корректное отображение

- [ ] Маршрут не выбран → панель полностью скрыта.
- [ ] Маршрут выбран, карандаш off → только название и цвет.
- [ ] Маршрут выбран, карандаш on → полный набор редактирования.
- [ ] При снятии выбора не залипают: имя, цвет, КП, линии, выбранный сегмент, кнопки.

### 1.6. Разводка ЛКМ

- [ ] ЛКМ по пустой карте без выбранного маршрута — ничего.
- [ ] ЛКМ по пустой карте при выключенном карандаше — ничего.
- [ ] ЛКМ по пустой карте в редактировании без текущей линии — ничего.
- [ ] ЛКМ по пустой карте в редактировании с текущей линией — добавить вершину в конец **этой** линии.

### 1.8. ПКМ — глобально

- [ ] ПКМ не включает карандаш.
- [ ] ПКМ на панелях, кнопках, пустой карте, линии, «плюсе» — ничего.
- [ ] ПКМ по вершине/КП в просмотре — ничего.

## Этап 2 (P1). Вершины, КП и модалка номера

**Цель:** привести поведение точек к ТЗ. Главное новое — модалка номера КП с валидацией. Удаление через ПКМ заменяет нижнюю корзину.

**Затрагиваемые файлы:**

- [georoute-frontend/src/components/Markers/Markers.tsx](../georoute-frontend/src/components/Markers/Markers.tsx)
- `georoute-frontend/src/components/NodeMarkers/NodeMarkers.tsx`
- [georoute-frontend/src/components/Map/Map.tsx](../georoute-frontend/src/components/Map/Map.tsx) (временная линия, обработчики)
- Новый компонент: `CheckpointNumberModal` (под `components/`)

### 2.2. Вершины

- [ ] В режиме просмотра вершины не видны.
- [ ] В редактировании видны вершины **только** выбранного маршрута.
- [ ] Клик по вершине в просмотре — ничего.
- [ ] Клик по вершине в редактировании — открыть модалку номера КП (НЕ автоматически становится КП).

### 2.3. Модалка номера КП

Новый компонент с валидацией по Zod / RHF.

- [ ] Открывается только по клику на вершину в редактировании.
- [ ] Запрещает номер, уже занятый КП этого маршрута.
- [ ] Кнопка «Сохранить» доступна только при валидном уникальном номере.
- [ ] Esc / Отмена — закрыть без создания.
- [ ] Пока открыта — клики по карте не добавляют вершины и не создают КП.
- [ ] После сохранения: вершина становится КП, обновить линию/список КП/«плюсы»/возможные сегменты.

### 2.4. КП

- [ ] Клик по КП в просмотре — ничего.
- [ ] Повторный клик по КП в редактировании — превратить обратно в вершину.
- [ ] Перетаскивание КП в редактировании — переместить, связанные линии перестраиваются.
- [ ] ПКМ по КП в редактировании — удалить КП/Match.
- [ ] После удаления КП: обновить список КП справа; не оставлять сегментов без двух КП на концах.
- [ ] После превращения КП → вершина: проверить и зачистить сегменты, опиравшиеся на этот КП.

## Этап 3 (P2). «Плюсы» и сегменты КП→КП

**Цель:** ввести строгое понятие «сегмент = только КП→КП», развести два поведения «плюса», реализовать создание/выбор/подтверждение/удаление сегментов.

**Затрагиваемые файлы:**

- `georoute-frontend/src/components/NodeMarkers/NodeMarkers.tsx` («плюсы»)
- [georoute-frontend/src/components/Lines/Lines.tsx](../georoute-frontend/src/components/Lines/Lines.tsx)
- [georoute-frontend/src/components/CurrentLine/CurrentLine.tsx](../georoute-frontend/src/components/CurrentLine/CurrentLine.tsx)
- `georoute-frontend/src/widgets/RightMenu/RightMenu.tsx` (список сегментов, кнопка «Подтвердить»)
- `georoute-frontend/src/providers/paths/path-reducer.ts` (модель сегментов)
- `georoute-frontend/src/services/types/Path.ts` (типы)

### 3.1. «Плюсы» — два режима

- [ ] «Плюс» между двумя обычными вершинами — вставить вершину между ними.
- [ ] Новая вершина появляется между теми же соседями.
- [ ] «Плюс» между двумя КП — создать новый сегмент КП→КП.
- [ ] «Плюс» между КП не вставляет обычную вершину.

### 3.2. Модель сегмента

- [ ] Сегмент = только линия КП→КП.
- [ ] Не считать сегментом: основной трек, его часть, линию между обычными вершинами, временную линию.
- [ ] Привести типы и редьюсеры к этому правилу.

### 3.3. Создание сегмента

- [ ] Создаётся только через «плюс» между двумя КП в редактировании.
- [ ] Без выбранного маршрута/при выключенном карандаше — нельзя.
- [ ] Принадлежит выбранному маршруту.
- [ ] Начало и конец — именно КП.
- [ ] Получает свой цвет, случайный и не совпадающий с другими сегментами маршрута.
- [ ] Создаётся неподтверждённым, отображается пунктиром.
- [ ] Появляется в списке сегментов справа.

### 3.4. Выбор сегмента

- [ ] ЛКМ по сегменту выбранного маршрута в редактировании — выбрать сегмент.
- [ ] Линия визуально выделяется на карте, строка справа выделяется.
- [ ] ЛКМ по сегменту другого маршрута — ничего.
- [ ] ЛКМ по сегменту при выключенном карандаше — ничего.

### 3.5. Подтверждение сегмента

- [ ] Доступно только: маршрут выбран + карандаш on + сегмент выбран.
- [ ] Кнопка «Подтвердить» под списком сегментов.
- [ ] Заменяет участок основного трека между теми же КП линией сегмента.
- [ ] Сегмент становится сплошным.
- [ ] Строка справа становится зелёной, поднимается выше неподтверждённых.
- [ ] Не подтверждает остальные сегменты автоматически.
- [ ] Основной трек не «подтверждается» и не попадает в правила сегментов.

### 3.6. Удаление сегмента

- [ ] Кнопка удаления справа удаляет только выбранный сегмент.
- [ ] Основной трек при этом не трогается.

### 3.7. Чистка UI

- [ ] Убрать «Старт» и «Конец».
- [ ] Убрать сценарии, где основной трек попадает в список сегментов как сегмент.
- [ ] Проверить все упоминания `segment`, `line`, `node`, `match`, `checkpoint` в коде.

## Этап 4 (P3). Видимость, «Притянуть к тропе», Esc, чистка панелей

**Цель:** финальная полировка — корректная видимость в обоих режимах, контекстная кнопка «Притянуть», обработка Esc, удаление нерабочих элементов UI.

**Затрагиваемые файлы:**

- [georoute-frontend/src/components/Lines/Lines.tsx](../georoute-frontend/src/components/Lines/Lines.tsx)
- `georoute-frontend/src/components/NodeMarkers/NodeMarkers.tsx`
- [georoute-frontend/src/components/Markers/Markers.tsx](../georoute-frontend/src/components/Markers/Markers.tsx)
- `georoute-frontend/src/widgets/BottomMenu/BottomMenu.tsx`
- `georoute-frontend/src/widgets/LeftMenu/LeftMenu.tsx`
- `georoute-frontend/src/widgets/RightMenu/RightMenu.tsx` (кнопка «Притянуть к тропе»)
- `georoute-frontend/src/main.tsx` или Map.tsx (глобальный Esc)
- `README_user.md`

### 4.1. Видимость — режим редактирования

- [ ] Видны КП, основной трек, вершины, «плюсы», все сегменты выбранного маршрута.
- [ ] Неподтверждённые сегменты — пунктир.
- [ ] Подтверждённые — сплошная линия.

### 4.2. Видимость — режим просмотра

- [ ] Видны КП, основной трек, подтверждённые сегменты.
- [ ] Неподтверждённые сегменты скрыты, **если** есть хотя бы один подтверждённый.
- [ ] Если подтверждённых нет — все сегменты видны пунктиром.
- [ ] Вершины и «плюсы» скрыты.
- [ ] Клик по линии — ничего не редактирует.
- [ ] ПКМ по карте — ничего.

### 4.3. Переключение и снятие

- [ ] Переключение карандаша сразу обновляет видимость вершин, «плюсов», сегментов.
- [ ] Снятие выбора маршрута скрывает редактируемые элементы.
- [ ] «Глаз» справа применяется только к сегментам; не превращает трек в сегмент.

### 4.4. «Притянуть к тропе»

- [ ] Без выбранного маршрута — кнопка недоступна/скрыта.
- [ ] Карандаш off — недоступна.
- [ ] Карандаш on, сегмент не выбран — притягивает только основной трек.
- [ ] Карандаш on, сегмент выбран — притягивает только этот сегмент (подтверждённый или нет).
- [ ] При выбранном сегменте основной трек не меняется.
- [ ] При отсутствии выбранного сегмента сегменты не меняются.

### 4.5. Esc

- [ ] Закрывает модалку номера КП без сохранения.
- [ ] Отменяет незаконченное добавление вершины.
- [ ] Убирает временную линию предпросмотра.
- [ ] Выходит из редактирования, если больше нечего отменять; маршрут остаётся выбранным.
- [ ] Esc не удаляет: маршрут, вершины, КП. Не сбрасывает выбор просто так. Не ломает список сегментов.

### 4.6. Нижняя панель

- [ ] Убрать корзину.
- [ ] Убрать частичный мэтчинг (если не работает).
- [ ] Убрать «Отменить»/«Вернуть» (если не работают).
- [ ] Убрать все визуально доступные, но нерабочие кнопки.
- [ ] Карандаш виден только при выбранном маршруте.

### 4.7. LeftMenu

- [ ] Убрать KML, пока не реализован.

## Порядок исполнения и зависимости

```text
Этап 1 (P0)  ──► Этап 2 (P1)  ──► Этап 3 (P2)  ──► Этап 4 (P3)
   модель        вершины+КП       плюсы+сегменты    полировка
```

Внутри этапа задачи можно вести параллельно, но **переходить к следующему этапу до закрытия предыдущего нельзя** — каждый следующий опирается на модель состояний и обработчики мыши из предыдущего.

### Контрольные точки

- **После Этапа 1:** карта корректно реагирует на мышь, выбор маршрута и карандаш работают, правая панель и индикатор согласованы. Можно отдать на промежуточное ревью.
- **После Этапа 2:** можно добавлять/двигать/удалять вершины и КП; модалка номера прошла валидацию. Этап даёт ощутимое улучшение UX даже без сегментов.
- **После Этапа 3:** сегменты как полноценная сущность; основной функционал ТЗ закрыт.
- **После Этапа 4:** все пункты чеклиста приёмки выполнены, README обновлён.

## Что не входит в этот план

- Бэкенд-изменения (если потребуются для серверной валидации номеров КП — отдельная задача).
- Переключение подложки карты — закрыто отдельным ТЗ [TZ_MAP_LAYERS.md](TZ_MAP_LAYERS.md).
- Тестовое покрытие (отдельной задачей после стабилизации модели состояний).
