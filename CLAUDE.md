## Project

GeoRoute is a route planner for the "May Walk" (Майская прогулка) event. It is a two-service application: a Spring Boot backend that fronts GraphHopper (routing/map-matching) and MinIO (GPX storage), and a React/Vite frontend with a Leaflet map UI.

## Repository layout

- `georoute-backend/` — Spring Boot 4 / Java 17 service (Maven).
- `georoute-frontend/` — React 19 + Vite + TypeScript SPA.
- `docker-compose.yaml` — Orchestrates frontend (nginx), backend, GraphHopper, MinIO, and a one-shot self-signed cert generator.
- `docs/` — Technical specs (`TZ_*.md`) for map layers and mouse UI behavior. Consult these before changing the relevant features.

## Common commands

Backend (run from `georoute-backend/`):
- `./mvnw spring-boot:run` — run the API on `:8080`.
- `./mvnw test` — run all tests.
- `./mvnw -Dtest=ClassName#method test` — run a single test.
- `./mvnw package` — build the jar (output in `target/`).

Frontend (run from `georoute-frontend/`):
- `npm run dev` — Vite dev server. Proxies `/api/*` → `http://localhost:8080/api/v1/*` (see `vite.config.ts`), so the backend must be reachable on 8080.
- `npm run build` — `tsc -b && vite build`.
- `npm run lint` — ESLint over the project.

Full stack:
- `docker compose up` — brings up frontend (nginx on 80/443), backend, GraphHopper, MinIO. Backend reaches GraphHopper at `graphhopper:8989` and MinIO at `minio:9000` via `app-network`.
- **First-time setup:** a routable OSM PBF must be placed at `georoute-backend/src/main/resources/graphhopper/maps/map.osm.pbf` before `docker compose up`. GraphHopper builds its cache from this file on first run (slow). Without it, the `graphhopper` container fails and the backend's routing calls error out.

## Architecture

### Backend (`org.urfu.georoute`)

API versioning is via Spring MVC's path-segment API versioning (`spring.mvc.apiversion.use.path-segment: 1`, default `1.0`). Routes are declared as `@RequestMapping("/api/{version}/...")` with `version = "1.0"` on each handler — when adding new endpoints, follow this pattern instead of hardcoding `/v1/` in the path. nginx and the Vite dev proxy both inject `v1` into the path; the backend itself does not.

Three service interfaces in `service/`, implementations in `service/impl/`:
- `GraphHopperService` (`GraphHopperServiceImpl`) — HTTP client to the GraphHopper container, configured via `graphhopper.url`.
- `MapMatchingService` (`MapMatchingServiceImpl`) — snaps a user-drawn GPX track to real roads using GraphHopper. The `/api/{version}/routes/match` endpoint consumes and produces `application/gpx+xml` via a custom `Constants.APPLICATION_GPX_XML_VALUE` media type with JPX (`io.jenetics.jpx`) for GPX parsing.
- `FileStorageService` (`MinioService`) — GPX persistence in MinIO bucket `routes` (see `application.yaml`). `RouteController` exposes list/get/save/delete on this bucket.

`config/` holds Spring `@Configuration` for the MinIO client, an `OkHttpClient`, web MVC settings (including registering the GPX `HttpMessageConverter` in `converter/`), and CORS if any. `Constants.java` centralizes the GPX media type so both controller and converter agree.

All external endpoints are env-overridable (`MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `GRAPHHOPPER_ENDPOINT`) and default to `localhost` for non-Docker runs.

### Frontend (`georoute-frontend/src`)

- Single-page app — `App.tsx` mounts `Map` plus three floating menus (`LeftMenu`, `RightMenu`, `BottomMenu`). No router despite `react-router-dom` being installed.
- State stack: Redux Toolkit (global) + React Query (`QueryClient` set up in `main.tsx`) for server state + React Hook Form + Zod for forms. `providers/MainProvider.tsx` composes app-level providers; `providers/paths/` holds the path-editing context that the menus and map share.
- Folder conventions: `components/` are leaf/presentational, `widgets/` are composed UI panels (the three menus), `pages/` is currently empty. `services/api/` is the axios client layer talking to the backend (`gpxSevice.ts` (sic — preserve the existing filename), `graphHopperService.ts`). `hooks/` and `lib/helpers/` are shared utilities.
- React Compiler is enabled via `babel-plugin-react-compiler` in `vite.config.ts` — do not add manual `useMemo`/`useCallback` for cases the compiler already handles; idiomatic React 19 is preferred.
- Right-click is globally suppressed in `main.tsx` (`document.oncontextmenu = () => false`) because the map uses right-click for its own gestures. Keep this in mind when adding context-menu features.
- Map editing uses `react-leaflet` + `react-leaflet-draw`. GPX import/export and "match current path" call the backend's `/routes` and `/routes/match` endpoints.

### Deployment topology

In Docker, nginx (the `frontend` container) terminates TLS with a self-signed cert generated by the `cert-gen` one-shot service into a shared `certs-data` volume, serves the built SPA, and reverse-proxies `/api/` → `backend:8080/api/v1/`. The browser never talks to backend/GraphHopper/MinIO directly. In dev (`npm run dev`), Vite plays the same proxy role.
